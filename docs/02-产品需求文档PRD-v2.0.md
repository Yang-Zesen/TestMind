## 1. 需求背景与当前现状

测试团队需要在需求频繁变化、测试资产分散、环境与数据准备复杂、自动化维护成本高的情况下，持续保障产品质量。TestMind 通过统一测试资产与流程，并提供 AI 辅助生成、分析和质量追踪，降低重复工作并提升问题定位效率。

产品覆盖以下测试流程:
- 测试策略制定与评审
- 根据需求文档与开发澄清编写测试用例
- 测试环境搭建与维护
- 测试数据备份与准备
- 测试用例执行与缺陷反馈
- 测试用例自动化
- 缺陷更正后的回归测试
- 测试报告写作与评审

## 3. 项目概述


TestMind 面向软件测试团队，目标是将需求、接口资料、项目风险、历史缺陷和测试经验转化为可追溯的质量资产，并管理 **测试策略与计划、环境和数据准备、测试设计与自动化、执行分析、缺陷协作、修复回归、报告评审和反馈改进** 全流程。AI 用于辅助生成与分析，策略、正式资产、环境操作和执行结果均保留人工审核授权；项目通过既有测试管理及基础设施平台集成，不重建通用项目管理或底层资源平台。

## 5. 产品范围

TestMind 的目标范围覆盖软件测试全生命周期，包括：

- 需求、接口、设计与开发澄清的接入、解析、追踪和变更影响分析。
- 测试策略与计划制定、风险识别、覆盖目标和进入/退出标准评审。
- 测试环境登记、健康检查、受控准备与清理，以及测试数据生成、导入、校验、备份恢复和生命周期管理。
- 测试用例设计、评审、去重、覆盖分析，及 API、UI/跨端等自动化脚本生成、验证和执行。
- 执行进度汇总、日志与失败分析、缺陷协作，以及缺陷修复后的影响分析和回归验证。
- 测试报告生成、评审、发布与追溯，和经授权的经验回流、质量度量及持续改进。
- 与禅道、代码/CI、测试执行环境、通知与报告服务等外部系统进行受控集成；不要求 TestMind 重建通用项目管理平台或底层计算资源。

```text
用户提交任务 → 任务受理（任务 ID、理解结果、当前状态）
需求/API 文档 + 项目知识/历史缺陷
  → 接口解析和因子提取 → 新用例草稿与覆盖检查 → 人工确认
  → 禅道正式用例 → 自动生成自动化脚本 → 人工确认
  → 隔离环境执行 → 报告/失败分析 → 人工确认缺陷或修订
  → 最终结果反馈（实际结果、证据、审批及回流状态）
  → 授权反馈入库/标注 → 下一轮检索与生成实际复用
```

已确认的测试资产方可进入后续执行流程；外部写入和脚本执行均须经过授权审批。

### 5.2 企业级目标能力与分阶段交付

TestMind 的产品目标面向企业级生产场景。需求范围描述目标能力全集，不表示这些能力均已实现、已部署或已通过生产验收；MVP 按阶段交付其中一部分，其余能力保留在产品规划和目标架构中，不因暂缓实现而从产品能力范围中删除。

需求、架构图、交付计划及验收材料应区分以下状态：

| 状态 | 定义 |
|---|---|
| 已实现并验证 | 有对应实现及可复核的测试、联调或运行证据；仅代码存在不视为生产验证 |
| 部分完成 | 已有部分实现，但目标流程、边界条件或生产验收尚未完成 |
| 已计划、尚未实现 | 已纳入产品交付计划，但尚无可用实现 |
| 暂缓 | 已识别并保留在目标能力范围内，当前阶段不交付 |
| 外部提供 / 按环境集成 | 由客户或部署环境提供基础设施，TestMind 通过标准接口集成；不表示 TestMind 内置该产品 |

各阶段须另行标明纳入的 MVP 范围、依赖和验收证据。目标能力、技术选型、当前实现状态和实际部署状态不得相互替代；企业部署所需的具体 SLO、容量、RPO/RTO 和安全基线，应在目标环境评估及基准测试后确定。

## 6. 功能需求

### 6.1 禅道集成与测试资产

| 编号 | 需求 | 验收要点 |
|---|---|---|
| F-01 | 接入禅道项目、成员、需求、用例和缺陷接口 | 查询真实授权数据；保存外部 ID、来源版本及同步时间；连接故障与无权限状态可区分 |
| F-02 | 对已确认的新用例和缺陷执行受控写入 | 返回禅道正式 ID；接口失败保留草稿与错误，不显示为已发布；重试不得重复创建 |

### 6.2 RAG 知识库

| 编号 | 需求 | 验收要点 |
|---|---|---|
| F-04 | 授权用户按项目/知识库上传 PDF、Markdown、TXT | 批量上传；查看处理状态、文件版本、失败原因；支持重建索引与删除 |
| F-05 | 解析文档并建立可追溯的知识索引 | 保留页码、标题等来源位置和版本；记录解析状态；无法识别的内容明确提示，不得静默漏入 |
| F-06 | 语义检索、关键词混合检索与重排序 | 检索前按项目权限过滤；比较向量、BM25 混合和重排效果；可配置去重和 Top-K |
| F-07 | 基于知识生成带来源的回答 | 可查询当前项目能力、已出现的缺陷、用例设计思路、测试环境搭建与手工测试执行方法；展示片段和文档/页码/标题引用，证据不足时说明不足 |

知识库包含受控共享测试方法、项目需求和接口说明、历史缺陷、框架规范以及经评审的用例与脚本。原文件与检索索引分别管理；更新或撤回后旧版本不得被召回。缺陷发生频率、影响排行和自动化率来自结构化数据，不由 AI 推断。

### 6.3 智能助手与任务编排

| 能力 | 职责 | 输入与输出 |
|---|---|---|
| 知识问答 | 基于授权资料回答项目知识、历史缺陷和测试方法问题，支持结构化统计 | 返回来源、适用项目、统计范围和数据时间；证据不足时说明限制 |
| 测试资产生成 | 辅助生成、分析和维护测试策略、用例、数据、脚本及报告 | 产物关联输入来源、版本和验证状态；未经审核不得成为正式资产 |
| 质量分析 | 查询需求、用例、脚本、执行、缺陷和回归关系，汇总质量进展 | 仅返回用户有权访问的数据，指标附统计口径 |
| 通用问答 | 回答通用测试与研发问题，并将项目查询和任务请求交由相应业务能力处理 | 说明路由和执行状态，不绕过权限、审批或执行限制 |

| 编号 | 需求 | 验收要点 |
|---|---|---|
| F-08 | 对用户问题按需纠错、指代消解并路由意图 | 保留原文；接口名/编号不被误改；歧义先澄清；意图识别能力可替换，不成为主链路的单点依赖 |
| F-09 | 编排 AI 助手、用例生成和失败分析流程 | 记录任务意图、检索来源、产物版本和审批节点；执行或写入前须取得明确授权 |
| F-10 | 管理对话上下文、任务状态与用户记忆 | 按用户、项目和会话隔离；设置数据保留期并支持用户查看、清除本人记录；缓存或临时服务不可用不得造成授权边界失效或业务记录丢失 |

各项 AI 能力可由统一入口调用；代码执行、外部写入和跨项目访问均须经过独立授权与审批。

**AI 节点通用边界：**每个 AI 节点均须限制输入与上下文、校验输出结构/类型、设置单次超时与任务截止时间，并返回可区分的成功、澄清、拒绝、失败或预算耗尽等终态及停止原因。纯分类、改写、问答或生成节点不因此强制引入 Agent 工具循环。

**工具、受保护数据与副作用控制：**仅对会调用工具、访问受保护数据或产生外部副作用的路径强制设置三道确定性控制门：①服务端基于可信身份/项目范围检查授权并限制可用能力；②模型只可在注册工具及 Schema/枚举约束内提出调用和类型化参数，模型不得授予权限；③服务端在执行前复核授权、参数、预算/时限，执行后校验结果契约并记录结果。优先复用现有意图识别做候选路由、已有授权/白名单和 Schema 校验；意图识别仅负责路由，不替代授权。任何一道门失败均不得调用下游或扩大访问范围。

**错误恢复：**可重试的依赖瞬时故障与可修复的模型结构/参数错误分开处理。前者使用有上限的指数退避（可加抖动）并受总截止时间约束；后者将脱敏、结构化错误反馈给模型进行有限次数自修复，并限制 Token 与时间预算。权限拒绝、业务拒绝及确定性校验失败不作为瞬时依赖错误重试；外部写入结果未知时先核实/对账，不盲目重放。达到上限后返回明确失败状态和停止原因。

## 8. 产品架构

正式主图并列提供 [draw.io 版本](diagrams/TestMind-单页完整流程.drawio) 和 [Mermaid 版本](diagrams/TestMind-单页完整流程.mmd)；[Mermaid 单页阅读版](diagrams/TestMind-单页完整流程.md) 与 [可缩放预览](diagrams/TestMind-单页完整流程-Mermaid.html) 用于审查。两份主图同步表达业务流程、条件分支、独立工作流和交付状态；具体模块设计见 TDD 第 2 节。

产品由以下逻辑能力组成，模块职责与技术选型见第 11 节：

- **工作台**：项目空间、测试资产、任务执行、质量分析、报表和系统配置。
- **业务服务**：身份与权限、工作流编排、资产管理、审批、审计和通知。
- **AI 服务**：知识检索、用例/数据/脚本生成、日志分析和报告辅助；支持配置模型服务并执行数据出域策略。
- **执行服务**：在隔离环境中运行获批的自动化及专项测试任务，保存运行状态和证据。
- **集成服务**：连接禅道、代码托管、CI/CD、环境管理、测试工具和通知平台；支持适配、重试和同步状态追踪。
- **数据服务**：管理结构化测试资产、知识索引、文件和运行记录，并执行项目隔离、访问控制、保留与删除策略。

## 9. 验收标准

| 类别 | 验收要求 |
|---|---|
| 业务闭环 | 需求文档、Swagger/OpenAPI、Postman Collection 各有可解析样例；同一授权项目内，至少一条新用例覆盖可核查的正/负/边界设计，经评审取得禅道正式 ID，再生成并确认自动化脚本、执行并查看完整报告 |
| 全流程目标 | 可从需求与澄清记录形成经评审的测试策略/计划；关联环境、数据、用例、执行与缺陷；修复后完成经审批的影响分析和回归；生成含覆盖、结果、风险和未执行项的报告并经人工评审发布；各流程环节均可追溯责任人、版本、状态和证据 |
| 环境与数据 | 环境健康检查能识别不可达/版本不符并阻止误报通过；数据集可按授权完成准备、备份恢复、执行后清理；敏感数据访问、脱敏和保留策略可审计 |
| API 契约测试 | 从 OpenAPI 样例生成待审的正向/负向/边界用例及数据；环境变量切换、Mock、数据驱动运行、CLI/CI 报告可用；接口定义变更能提示关联用例复核 |
| 回归与报告 | 修复项可追溯到影响分析、获批回归集及前后执行证据；未执行/部分完成标记准确；报告中的指标可下钻到原始运行和缺陷记录，未经评审不能标为正式发布 |
| 数据飞轮 | 人工确认缺陷或修订后，受审资产回流；下一轮检索/生成实际引用其有效版本，并展示来源、撤回效果及质量前后对照 |
| 知识问答 | 支持文档解析、带来源引用的回答和内容更新/删除；重复内容不产生重复有效知识，撤回后旧版本不可召回，跨项目不可见 |
| 执行与安全 | 未确认脚本不可运行；改动使旧审批失效；两个任务的临时变量、日志和报告互不覆盖；超时和收集错误可识别 |
| 智能分析与调度 | 失败分类模型经过独立数据评估后方可发布；获批测试任务可按计划或事件运行并记录状态；通知失败重试不得导致重复执行 |
| 外部集成 | 禅道读取、正式用例写入与人工确认提单均返回可追溯 ID；写入失败可查看且不能视为验收通过 |
| AI 与质量分析 | 知识回答带来源；测试资产生成可编辑并需审核；资产关系和质量指标按权限查询并展示统计口径；通用问题与项目任务正确分流 |
| 专项测试 | 性能与安全任务仅在授权环境执行；结果包含工具/版本、环境、运行 ID、覆盖范围和原始证据；已验证发现可复现，未完成或未运行任务不得标记为通过 |
| 权限与同步 | 员工不得查询他人个人进度；经理/TSE 仅能查询获授权项目成员；撤权后旧图谱聚合与报告链接立即不可读，即使关系副本尚未更新；Webhook 重复或失效时无越权/重复资产，API 增量同步可补偿 |
| 任务与反馈 | 提交任务后返回任务标识和当前状态；完成、失败、超时或拒绝均有最终结果及证据；页面刷新或服务重启不丢失状态，撤权后不可继续访问 |
| 数据治理 | 知识、训练和评估数据均有来源、授权、版本和脱敏记录；评估集不进入训练；新反馈须经准入审核后方可复用 |

AI 能力须基于版本化评估集验证，并报告检索相关性、用例覆盖与正确性、脚本可运行率、失败分析准确性及人工采纳率；评估报告注明样本范围、环境、方法和结果，质量门槛由项目验收基线确认。

## 10. 非功能需求

本节定义企业目标能力。具体组件、服务等级和验收阈值按部署形态、客户环境和容量基线确定；架构支持或接口兼容不等于相应组件已内置或已部署。

| 类别 | 企业级目标要求 |
|---|---|
| 可观测性 | 对 API、主图/子图、RAG、模型、数据库、外部集成和 Worker 提供可关联的结构化日志、Metrics 与分布式 Trace；以 task_id、trace_id、tenant/project/user 等受控维度关联，避免高基数标签和敏感信息泄漏。AI 决策事件记录节点/路由、授权与工具结果、模型/Prompt/Schema 版本（可得时）、稳定错误码、结果类别、停止原因、耗时/用量及证据版本标识，以重建可观察的决策轨迹；不得记录隐藏思维链。原始提示词、完整工具参数/返回体和回答正文默认不进入运行日志；排障确需正文时使用单独受控、脱敏且有保留期限的诊断存储。支持业务、技术、AI 与成本视图，错误率、延迟、积压、超时、审批等待及同步失败告警；定义 SLI/SLO、统计口径、告警分级和升级策略。 |
| 安全、身份与权限 | 执行租户、组织、项目、用户、会话及服务身份隔离和最小权限；支持与企业身份源集成、身份/成员生命周期同步、角色授权、服务账号和即时撤权。API 防护提供适当的认证、授权、限流、请求大小/速率限制、超时及防重放控制；WAF、IP 策略等由部署环境或安全平台按风险提供。 |
| 密钥与供应链安全 | 密钥、模型凭据、数据库密码和签名密钥通过环境密钥服务或 KMS/Vault 兼容接口管理，支持最小权限、轮换和泄漏处置，不得写入代码、日志或普通业务数据。建立依赖/镜像漏洞扫描、版本锁定、补丁流程和 SBOM 产出能力。 |
| 数据保护与隐私 | 数据按敏感级别管理，覆盖传输/存储加密、脱敏、访问审计、数据驻留/出域策略、保留期限、导出、更正和删除。策略覆盖原始文件、数据库、缓存、向量索引、图谱投影、日志、备份及第三方模型处理；未经授权的数据不得用于训练或供应商改进。 |
| Agent 与工具执行治理 | 工具须注册、版本化并声明 Schema、权限和风险级别；对工具、受保护数据和副作用路径，按服务端可信身份/能力授权、模型受限提议、服务端执行前后确定性复核三道控制门执行；调用时校验用户/项目授权、参数、预算、超时、并发和结果边界，记录审计证据，并对拒绝/未知工具安全失败。意图识别可复用作候选路由，但不得代替授权。关键写操作和高风险操作支持人工审批。脚本及主动测试只在授权范围、受隔离执行环境和资源/网络/文件/凭据策略约束下运行，任务间数据隔离并可清理。 |
| AI 与模型治理 | 记录模型供应商、模型/参数版本、Prompt 版本、工具版本及变更审批；支持评估、灰度、回滚和成本/Token 配额。建立独立版本化评估集，覆盖意图、RAG 召回与排序、引用正确性、生成质量、幻觉/拒答、提示注入、越权工具调用和敏感信息泄漏；评估数据不得未经授权混入训练。线上质量指标须注明自动采集或人工标注口径。 |
| 可靠性与任务恢复 | 长流程采用显式状态机，定义合法迁移、取消、超时和终态；每个 AI 节点限制输入/上下文、校验输出、设置超时/截止时间并报告停止原因。任务、请求和事件具备可追踪的统一标识与幂等语义。依赖瞬时故障使用带上限的指数退避（可加抖动）和总时限；可修复的结构/参数错误使用独立、有限次数且受 Token/时间预算约束的模型自修复。权限拒绝、业务拒绝和确定性校验失败不重试；外部写入结果未知时先核实/对账。外部模型、检索、数据库、集成和 Worker 调用配置超时、熔断/降级策略；异步任务提供排队、优先级/配额、失败分类、死信查看/重放和人工恢复能力。跨系统状态通过 Outbox、补偿或对账保证可恢复，不承诺分布式事务。 |

| 外部集成治理 | 连接器支持凭据轮换、健康状态、API/事件版本兼容、签名校验、重复/重放防护、限流、超时、游标/水位、补偿及失败可见性。外部系统不可用时保留本地任务/草稿状态，不得把未同步误报为成功；接口变更须有契约测试和升级策略。 |
