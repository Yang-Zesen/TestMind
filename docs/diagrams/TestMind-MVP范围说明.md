## 主图与结果路径

```text
用户输入 → 受理/鉴权/状态 → 拼写纠错 → 意图识别 → 按 intent 路由
  dialogue → 指代消解 → 问答入口 → direct / retrieval → 问答结果
  test_case_generation → 资料解析 → 因子/用例 → 评审 → 禅道正式 ID
  graph_query → 参数提取 → 服务端权限 → 受限查询/指标 → 结果/审计
  script_generation → 红色脚本子图（暂缓）
  歧义/异常 → 澄清与补充
已纳入业务结果 → 统一结果返回 → 持久化反馈/任务资产 → 结束
```

拼写纠错、意图识别和指代消解已放回主图中央流程。指代消解只适用于问答意图，与现有 `builder.py` 的职责边界一致；这次没有修改业务代码。其他意图的目标子图接入状态仍以图中节点说明为准。

用例任务在真实禅道写入成功、保存正式 ID 后可直接结束；不再要求继续生成脚本。写入失败保留草稿、错误及同步状态，不能报告发布成功。问答和图谱通过同一结果出口返回；后台流程独立执行，不要求用户每次请求都运行整条入库或同步链。

## 保留的约束

- 服务端身份与项目权限、撤权即时生效、会话隔离、原件/结果访问控制。
- 用例人工编辑/批准/拒绝、版本绑定、外部写入幂等与失败反馈。
- 来源、版本、负责人、真实状态和证据引用；状态持久化与恢复。
- 知识更新/撤回后的有效版本过滤，图谱先授权后统计，外部事实来源不被投影替代。
- 获批模型、密钥引用、数据最小化/脱敏、出域策略和调用审计。

绿色 36 个节点的范围仍限于核对记录中的代码能力。生产身份接入、原生禅道契约、实库/真实账号联调、RAG 统一 DTO、部分指标及跨业务装配等不能据此宣称完成。

PRD F-01～F-50 映射保留在每个相关节点的 `prdRefs` 属性和节点文字中。脚本/执行相关 F-14～F-17 的完整闭环、专项测试、修复回归及全计划报告仍是后续目标。无色/绿色范围是本次交付安排，不是对整条 PRD 需求验收通过的声明。
